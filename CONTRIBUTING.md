# Contributing

Thanks for your interest in contributing! Bug reports, documentation fixes, tests, and code contributions are welcome.

These guidelines are the default for repositories under JangMan-J. Repository-specific instructions take precedence.

## Before you start

- Read the repository's README and contribution instructions.
- Search existing issues and pull requests for related work.
- For substantial changes, open an issue first to discuss the problem and proposed approach.
- Keep each contribution focused on one problem.

## Report a bug

Open an issue in the affected repository. Include:

- A clear description of the problem.
- Steps to reproduce it, preferably with a minimal example.
- The expected result and the actual result.
- Relevant versions, operating system, and logs.

Remove passwords, tokens, and personal information from examples and logs.

## Suggest a feature

Explain the problem that the feature solves. Describe your proposed solution and any alternatives you considered.

## Submit a pull request

1. Fork the repository and create a branch for your change.
2. Follow the repository's instructions to install dependencies and configure your environment.
3. Follow the existing code style and project conventions.
4. Add or update tests for behavior changes.
5. Update documentation for changes that affect users.
6. Run the relevant tests, formatter, and lint checks documented in the repository.
7. Open a pull request with a clear title and description.

In the pull request description:

- Explain what changed and why.
- Link related issues.
- Describe the checks you ran and their results.
- Mention any checks you did not run and explain why.
- For visual changes, include screenshots.
- Highlight breaking changes or migration steps.

Avoid unrelated refactors, generated files, and dependency changes unless the contribution requires them.

## Review

Maintainers review contributions as time permits. A proposal or pull request does not guarantee acceptance.

Keep discussions respectful and focused on the work. For questions about feedback, ask for clarification in the pull request.

## Security reports

Do not disclose security vulnerabilities in public issues or pull requests.

Follow the repository's SECURITY.md instructions. If private vulnerability reporting is available, use **Security → Report a vulnerability**.

If neither option exists, ask the maintainer for a private reporting channel without including vulnerability details.

## License

Submit only material that you have the right to contribute. Contributions must be compatible with the repository's license.
