# Security Policy

This policy is the default for repositories under JangMan-J. Repository-specific security policies take precedence.

## Report a vulnerability

Do not report security vulnerabilities in public issues, pull requests, or discussions.

1. Open the affected repository on GitHub.
2. Select **Security**.
3. Select **Report a vulnerability** to open a private report.
4. Describe the vulnerability, its impact, and steps to reproduce it.
5. Submit the report.

Include these details:

- The affected project and version or commit.
- A description of the vulnerability and its potential impact.
- Steps to reproduce the issue or a minimal proof of concept.
- Any relevant configuration or prerequisites.
- Any proposed fix or workaround.

Remove passwords, access tokens, and personal information from the report.

If the affected repository has no private reporting form, use the [private reporting form in JangMan-J/.github](https://github.com/JangMan-J/.github/security/advisories/new).
Identify the affected repository in your report.

For vulnerabilities in upstream projects, use the upstream project's private reporting channel.

## Security updates

Support for specific versions depends on the repository. This default policy does not guarantee security updates for older releases.

Consult the affected repository's documentation and release notes for support details and available fixes.

## Disclosure

Keep vulnerability details private until maintainers and reporters agree on disclosure, where possible.

Maintainers review reports as time permits. This policy does not promise a response deadline, a fix deadline, or a bounty.

## Responsible testing

Test only systems that you own or have explicit permission to test.
Do not access other people's data, disrupt services, or perform destructive tests.
